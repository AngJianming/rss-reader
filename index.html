    Leetcode - 173. Binary Search Tree Iterator
    🧠 Approach Why In-order? In-order traversal (Left → Root → Right) returns values in sorted order for a Binary Search Tree (BST). We want to simulate this traversal step-by-step. One could pre-compute the entire in-order list, store it in an array, and just use an index to iterate. We simulate in-order traversal lazily using a stack: At initialization, we push all the leftmost nodes from the root to the bottom. When next() is called: We pop the top node (which is the current smallest). If it has a right child, we push all left children of the right subtree into the stack. This ensures the top of the stack always holds the next smallest element. ✅ Code (JavaScript) var BSTIterator = function(root) { this.stack = []; this._pushLeft(root); }; BSTIterator.prototype._pushLeft = function(node) { while (node) { this.stack.push(node); node = node.left; } }; BSTIterator.prototype.next = function() { const node = this.stack.pop(); if (node.right) { this._pushLeft(node.right); } return node.val; }; BSTIterator.prototype.hasNext = function() { return this.stack.length > 0; }; Operation Time Complexity Reason next() Amortized O(1) Each node is pushed/popped once hasNext() O(1) Just checks if the stack is non-empty Constructor O(h) h = height of tree (worst case: all left) | Space Complexity | O(h) | Stack holds up to h nodes (leftmost path) | This iterator gives BST elements in sorted order using an explicit stack. It’s efficient and lazy — avoids generating full traversal. Perfect for scenarios where you don’t want to load all nodes at once.  ( 3 min )
