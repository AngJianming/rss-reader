    BigQuery time travel is pretty neat

In a setup where things like scheduled pipeline runs are constantly updating the table, it helps a lot to be able to see what a table looked like at a specific point in time. The timestamp has to be within your time travel window, which can be between two to seven days (7 by default). For a full restore, copy the historical data into a new table. If you only need to repair the current table, copy the time travel data to a temp table, then update the current table using the temp table as source.
