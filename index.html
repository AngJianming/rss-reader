    Standard web glTF/OBJ viewers usually run out of memory or stall for minutes when given multi-gigabyte industrial or BIM assemblies. GitHub: https://github.com/zly258/3dbrowser Tech Stack: React 19, Three.js, TypeScript, WebAssembly (web-ifc, occt-import-js) When a 2+ GB BIM or plant assembly is exported to plain glTF/JSON, parsing and expanding it in the browser easily multiplies memory usage several times over, crashing the tab. Even if it fits in memory, hundreds of thousands of separate meshes produce too many WebGL draw calls. 3dbrowser is designed around six-figure component counts from the ground up: NBIM v11 Single-File Container: Packs geometry, properties, and the structure tree into one binary container (with fixed-point coordinate quantization and columnar blocks). Octree Chunk Streaming: Instead of waiting for the entire file to download before rendering, chunks stream in by spatial octree so the first frame appears in ~3–4.5s. Three.js BatchedMesh: Merges heterogeneous components sharing materials into far fewer draw calls to maintain smooth frame rates. On-Demand Property Resolution: Component metadata is resolved when selected rather than kept resident in memory alongside geometry. Tested on a 2.9 GB NBIM file (231,353 components, 186 million rendered triangles) in a single browser tab while keeping JS heap under ~3 GB. Includes distance/angle/point measurement, real-time sectioning planes, hierarchical scene tree search, and marquee box selection.
