    Access token vs refresh token
    Refresh Token:- A Refresh Token is a long-lived token used to generate new access tokens without login the user again. Refresh tokens must be stored securely (server-side only) Once the Refresh token is expire user must login again (re-authentication need). Access tokens are short-lived token (15 minutes). When they expire, instead of making the user log in again, the app quietly uses the refresh token behind the scenes. The user login and gets both an access token and a refresh token Your office keycard expires every day at midnight. Instead of going back to reception every morning, you have a special master card that automatically issues you a new keycard. The master card much longer, but is stored securely in HR (your server),not to our shirt. An Access Token is a short-lived(15 min) token that allows a user to access protected resources. Access Token are stored in the HttpOnly cookies. Used to access APIs and protected routes and send in every request. Access token use the refresh token to get new Access Token. If someone steals an access token, the damage is limited because it expires quickly. Why not just use one token? If we use only a long-lived access token: The user stays logged in for a long time. If we use only a short-lived access token: Security improves. But users would have to log in repeatedly. Using both tokens gives us the best of both worlds: Access Token → Better security.
