In Go we use go mod init module-name while in Zig it's just zig init In Zig, "module paths" are not specified as in Go because there is no exact correspondence between package import and its URL: this approach seems more flexible but I must also say less standardized. // Go package main import ( "fmt" ) func main() { fmt.Println("Hell world") } // Zig const std = @import("std"); pub fn main() !void { std.debug.print("Hell World", .{}); } In both languages, main is the reserved function as the entry point for the application. Both don't accept input parameters and arguments passed must be handled with standard library functions. As for the return, Zig is consistent as it treats main like all other functions (error or value, in this case void) while in Go the success return is implicit and the error must be handled inside the function typically with an os.Exit(1) or a panic("error!"). To run our application we have a very similar command between the two languages. In Go we do go run main.go zig run src/main.zig The same goes for a simple build go build main.go zig build src/main.zig Note the creation of a zig-out/bin folder where we will find the generated binary.
