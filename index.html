    Consistent Hashing
    Problem Statement We need to distribute keys (data, requests, cache entries) across multiple servers. This causes? Massive data movement Cache invalidation Network overhead We need a way to minimize key movement when servers change. The Solution: Consistent Hashing Instead of modulo arithmetic, consistent hashing: Maps both servers and keys onto a circular hash space (a ring). Assigns each key to the next server clockwise. This small change ensures that when servers are added or removed, only a small subset of keys move. Example Place 3 servers: 0 ----10(A)----40(B)----80(C)----99 -> back to 0 Step 2 — Add Keys Assignment Rule: Result: Distribution: Removing a Server Remove Server B (40). 0 ----10(A)---------80(C)----99 Which keys move? New distribution: Only one key moved. New ring: 0 ----10(A)----30(D)----80(C)----99 Which keys are affected? That is: New distribution: Again, only one key moved. Why Consistent Hashing Is Better Than Traditional Hashing ? hash(key) % N If N changes (e.g., 3 → 4 servers): Almost all keys get reassigned. Massive reshuffling occurs. Consistent Hashing Removed → only its keys move. Added → only nearby keys move. Movement is proportional to 1 / number of servers, not the entire dataset. Takeaway Consistent hashing minimizes data movement by placing servers and keys on a circular hash space and assigning each key to the next server clockwise. That design makes distributed systems scalable and stable.  ( 4 min )
